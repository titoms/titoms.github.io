# LIGNE ÉDITORIALE — FullStackChris

## 1. Objectif du document

Ce document sert de référence éditoriale pour le Second Brain, les articles de blog, la newsletter, les posts LinkedIn/X, les carrousels, les scripts vidéo et les freebies du site `fullstackchris.dev`.

Le but est de garder une ligne cohérente :

> Aider des founders, freelances, développeurs et petites équipes à clarifier, construire et lancer des applications web avec React, Node.js, TypeScript et des workflows IA pratiques.

---

## 2. Positionnement central

### Phrase de positionnement

> Full-stack web development, AI workflows and technical coaching for builders.

### Promesse

> I help founders, freelancers and small teams clarify, build and launch web projects using React, Node.js, TypeScript and practical AI-assisted development workflows.

### Méthode centrale

**AI Clarity Framework**  
_Subtitle: The solo founder web app development method_

Étapes :

1. Idea — clarify the target user, idea and problem.
2. Scope — define the MVP, useful features and remove unnecessary complexity.
3. Design — naming, branding, design system and first product screens.
4. Stack — choose tools, technologies, hosting, database, AI and payment stack.
5. Workflow — set up the development and AI-assisted workflow.
6. Roadmap — plan phases and milestones.
7. Build — implement the first phase.
8. Autonomy — help the user continue independently.

## 10. Structure d’article blog

Chaque article doit inclure :

```md
# SEO Title

Short intro:
- who this is for
- what problem it solves
- what the reader will learn

## The Problem

Explain the real pain point.

## Why It Matters

Connect to business, product or development outcomes.

## The Framework / Approach

Give a clear method, checklist, decision tree or workflow.

## Practical Example

Use:
- a real project,
- a client-like scenario,
- Keevo / Edumation / Singuessr / Railguessr,
- or a realistic fictional example.

## Common Mistakes

List 3–7 mistakes to avoid.

## Recommended Tools

Mention tools only when relevant.

## Action Checklist

Give practical next steps.

## Related Service CTA

Example:
Need help applying this to your project? Book a 1-hour coaching session or explore the AI Clarity Framework workshop.

## FAQ

Add 3–5 questions.
```

Longueur recommandée :
- 1200–2000 mots pour articles piliers.
- 800–1200 mots pour articles tactiques.
- 2000+ mots seulement pour deep guides.

## 11. Structure LinkedIn post

### Format recommandé

```txt
Hook
→ Problem
→ Opinion / lesson
→ Concrete breakdown
→ Actionable takeaway
→ Soft CTA / question
```

### Exemple

```txt
AI can help you build faster.

But it can also help you create a mess faster.

The problem is not the tool.
The problem is asking AI to code before you have:

1. a clear scope
2. a stable data model
3. a realistic roadmap
4. a design direction
5. a definition of “done”

This is why I use the AI Clarity Framework before coding.

It turns an idea into:
→ MVP scope
→ stack decision
→ workflow
→ roadmap
→ first implementation phase

AI is much more useful when it has context.

What do you usually define before asking AI to build?
```

## 12. Structure carousel LinkedIn

### Format recommandé

6 à 12 slides.

```txt
Slide 1 — Strong title / promise
Slide 2 — The problem
Slide 3 — Why it happens
Slide 4 — Mistake / insight 1
Slide 5 — Mistake / insight 2
Slide 6 — Mistake / insight 3
Slide 7 — Framework / checklist
Slide 8 — Example
Slide 9 — Action steps
Slide 10 — CTA
```

### Règles

- 1 idée par slide.
- Très peu de texte.
- Gros titres.
- Contraste fort.
- Design cohérent.
- CTA doux : freebie, article, newsletter.
- Pas de lien externe obligatoire dans le post principal si tu veux tester la portée.
- Mettre éventuellement le lien en commentaire.

### Formats adaptés

- Frameworks.
- Checklists.
- Mistakes.
- Decision trees.
- Before/after.
- Project breakdowns.
- Tool workflows.

```txt
Repurpose this article into:
1. A LinkedIn opinion post
```

```txt
Review this article for:

5. SEO alignment

8. Avoiding generic AI writing
```

## 18. Mesure et optimisation

À suivre chaque semaine :

- article views ;
- source trafic ;
- LinkedIn impressions ;
- LinkedIn comments ;
- carousel saves/downloads ;
- newsletter signups ;
- freebie downloads ;
- service page visits ;
- contact clicks ;
- Stripe clicks ;
- bookings.

À améliorer selon données :

```txt
High impressions, low clicks:
→ improve CTA and link placement.

High page views, low conversion:
→ improve service offer, proof, pricing, FAQ.

High carousel engagement, low site traffic:
→ stronger freebie CTA.

High blog traffic, low signup:
→ add content upgrade / freebie.

High newsletter signup, no service inquiry:
→ add welcome sequence and clearer service bridge.
```

## 19. Règle finale

Chaque contenu doit répondre à au moins une de ces fonctions :

1. Attirer.
2. Éduquer.
3. Prouver.
4. Capturer un email.
5. Convertir vers un service.
6. Renforcer la marque personnelle.

Si un contenu ne fait aucune de ces choses, il n’est pas prioritaire.
